## 3. 安全性：相邻十字 vs 阈值

**(a) 几何结构上不会补到相邻十字**：窗口单步半径 = half = min(win/2, 0.125×pitch)；本组 pitch=9455/13447px，half=600px；即使按 `max_iter=5` 的最坏"逐窗漂移"上限 5×600=3000px，也 < 半间距（4727/6723px），**看不到、也走不到相邻十字**。风险不在邻点。

**(b) 0.25/0.5/0.75×pitch 三档阈值全部无鉴别力**：正确兜底的 d_seed 最大 38px；而"空白反例"（把种子放在两十字中点/远离十字处，共 12 处）兜底返回点的 d_seed = 47–1066px，全部远小于三档阈值（2364–10084px）→ **三档都会 100% 接受**（正确 7/7、空白 12/12），阈值对"补错"零拦截：

| 阈值 | 正确兜底点（7） | 空白反例（12） | 相邻十字误补 |
|---|---|---|---|
| 0.25×pitch（2364/3362px） | 7/7 接受 | **12/12 接受** | 结构上不可能 |
| 0.5×pitch（4727/6723px） | 7/7 接受 | **12/12 接受** | 结构上不可能 |
| 0.75×pitch（7091/10085px） | 7/7 接受 | **12/12 接受** | 结构上不可能 |
| 0.005×pitch（47/67px） | 7/7 接受（d≤38） | 0–1/12（仅 47.4px 擦边） | 不可能 |
| 0.5×win（win 161–401 → 80–200px） | 7/7 | 2/12 | 不可能 |

空白反例实测（种子在空白处，refine 仍返回点且被 0.5×pitch 接受）：0006 d=334.2/369.2/470.1/493.8/778.5/1066.0px；0008 d=47.4/67.8/95.3/235.6/459.7/533.2px；返回点距最近真实十字 **4490–8388px（≈0.5×pitch）**，即"标准"的假点。

**(c) 根因：`refine_manual_point` 永不失败**。`cross_detector.py:558-595` 的实现里没有任何"无有效目标返回 None"的出口（docstring 说会返回 None，实际只 break 后返回 cx,cy）→ 兜底链路 **100% 会产出一个点**；当前方案再用一个恒为真的距离阈值去接受它，等于"失败点永不失败"，直接触碰红线 2（失败必须报 DETECT_FAIL、不做假兜底）。

**(d) 参数放大误差**：窗口过大（1200，half=600）时，质心被窗口内背景/散斑/发光渐变拉偏。win 扫描（对独立 E 参考）：
- 0006 六个失败点误差：win=81 → 35–56px；121 → 12–40px；**161 → 0.6–2.2px；241 → 0.7–2.5px；321 → 0.2–2.4px；401 → 0.8–3.6px**；601 → 0.2–5.2px；801 → 2.1–8.2px；**1201 → 4.7–20.0px**。
- 0008 idx2：win=81→49.6px；121→37.5；161→7.5；241→16.2；321→10.8；401→9.7；601→11.7；801→9.7；1201→6.2px（该十字本身对质心法有 ~6px 偏置，见 §5）。
→ 方案里的 `clamp(0.25×pitch,81,1200)` 在本组图恰好夹到 **1200（最差区）**；建议 win 取 **161–401px**（≈0.012–0.02×pitch，约 4–9 倍线宽；0008 实测线宽约 45px）。取 win=321 时 0006 补回误差 ≤2.4px（≤0.013mm），0008 idx2 约 10.8px。

## 4. 建议（可直接落地）

1. **win**：`win = int(round(min(401, max(161, 0.017*pitch_px))))`（本组：0006→229、0008→161）；不要用 `0.25*pitch` 再夹 1200。
2. **接受阈值**：`d ≤ max(20, 0.005*pitch)` 且 `d ≤ 0.5*half`（未跑到窗口边缘）；0.25/0.5/0.75×pitch 均不建议（形同虚设，实测全部放行）。
3. **必须加局部有效性校验**（否则仍是假兜底）：对 refined 点开小 ROI 跑一次 `detect_cross_in_roi`（或复用 `_cross_shape_validate` + `_confidence_score`），要求 `ok=True` 且 `conf ≥ conf_low(0.5)`；不通过则维持 `DETECT_FAIL`（红线 2）。
4. **留痕**：`method="local_retry"` 之外，把 `d_px / conf / win / 局部 SNR` 写入结果与报表诊断区，供事后判定可信度（当前方案无置信度信息，用户无法区分"真补回"与"补到亮斑"）。
5. 若坚持"尽量凑 9/9"，建议把 local_retry 结果单独标注（如状态 `OK(local_retry)` + 置信度列），并在验收统计中区分"直接检出 / 兜底检出"，避免把 0.10mm 级误差当成正常检出参与 RMS 达标判断（红线 4）。

## 5. 数据质量问题（顺带发现，影响"真值"使用）

- `truth_points_full.json` 的 **0006 row1col3**（series idx8 附近）记录为 (28194.1,1564.9)，但模板匹配+C+B+E 四种独立方法在多种子下都收敛到 **(28156.7,1571.1)**（互差 <1px），相差 **~38px（0.20mm）** → 该真值点错误（疑似其 scale≈0.55 路径在该处误配）。复核中已用独立值替代。
- `truth_points_full.json` 的 **0008 row3col3**（series idx2）记录 (26163.4,22739.9)，与独立 C/E 中心 (26168.3,22742.9) 差 ~5.7px；其 `attempts` 里恰有 `fallback: refine_manual_point, idx:2, d_px:14.2` 记录 → 该"真值"很可能是兜底自身产物（自证），不能作为校验兜底精度的基准。**建议真值文件对"由兜底/单方法产生的点"标注来源与不确定度，禁止循环自证。**
