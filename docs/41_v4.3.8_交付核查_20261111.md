## 二、结论

### **有条件通过（包本身可交付；两条对外表述须更正 + 一条证据须补）**

**支持"通过"的硬证据**
1. 包身份可复核：sha256 `fe934037…3081e`、100,403,130 B、255 entries，两处副本同一物。
2. **打包洁净度合格**：logs/temp/npz/xlsx **0 条**；含更新说明与 `_internal/python314.dll`；payload 240 文件 + 说明。
3. zip 内 exe 与 `_dist` exe md5 一致（`e9dc6d77…1b0a`），且 `ZipInfo 23:14:46` 晚于最新源码 `i18n.py 23:13:50`。
4. **门禁全绿**：门1 PASS（45/0）、门2 PASS、门3 PASS、`v43_ui_test` PASS、`selfcheck --require-baseline` PASS；基线正确（3.14.7 / PyInstaller 6.22.3 / hooks 2026.9），PROJ 指向 `src_v3.4_UI重构`（红线 10 有日志证据）。
5. 包内 PYZ 独立校验：v4.3.8 边缘拟合/中线/兜底留痕实现符号齐备。

**为什么只给"有条件"**
- **P1-A（必须更正）**：`识别过程_0003_20261111` **不是发布版 exe 产出**。三重反证：`识别过程.log` 只由 `tools/export_debug_process.py` 写出（格式逐字对应）、该工具**不在包内**、证据 mtime（23:13:16–17）**早于** exe（23:14:47）与 zip（23:15:19）。报告 39_ 与更新说明的"已用发布版重跑"应改为"源码树 + CLI 工具离线导出"。
- **P1-B（必须更正）**：`24/25 / 18-6-1 / P5 DETECT_FAIL` 是 **CLI 直调 `detect_points`（无 local_retry、无摆正角）** 的结果；**同一张图、发布版 GUI 实测为 25/25**，P5 被 `local_retry:edge_center`（conf 0.9）补回，`质心兜底 0 点`。两者不可互相替代表述。且**点号口径不同**（证据 P1=左上角；发布版默认 P1=左下角），"P5"不是同一点。
- **P1-C（建议补证）**：0006 / 0013 / 0009 的"25/25"回归**无任何归档证据**（全盘无对应识别过程目录/日志），不可复核。

> 结论措辞建议：**v4.3.8 包可交付**；但对外材料中"24/25、P5 DETECT_FAIL、已用发布版重跑"三处需按 §三 更正，否则属"宣称与事实不符"。
