## 3. 根因（已用数值复现）

### 3.1 代码链路

```
gui/main_window.py
  _display_src()            → 返回 _preview_src（若存在）否则 self.src   ← 2026-10 修 G07 时新增
  _pv(lx, ly)               → lx / _display_src().preview_scale           ← 用"显示图"的比例
  _refresh_pick_marks()     → s = self.src.scale;  _pv(ox/s, oy/s)        ← 用"主流程图"的比例
  _redraw_marks()           → 同样 _pv(gx/s, gy/s)
```

`_preview_src` 只在 `_show_calib_preview()`（棋盘格预览）里被赋值：

```
_show_calib_preview(chess)  →  _preview_src = chess
```

而 `_on_image_loaded()`（导入相纸/任意扫描图的唯一入口）**从未把 `_preview_src` 切回相纸图**。

### 3.2 触发条件（正好命中 14 的流程）

1. 先做标定 → `_preview_src = 棋盘格图`
2. 再导入黑相纸 → `self.src = 相纸图`，但 `_preview_src` **仍是棋盘格图**
3. 点选起始点/建系 → `/ self.src.scale`（相纸的真实比例） ÷ `棋盘格图.preview_scale`（错误比例）
4. 两张图尺寸/降采样比例不同 → **整组标记按比例偏移**

棋盘格绿十字之所以正常：标定时显示图就是棋盘格，`_display_src()` 正确，比例自洽。

### 3.3 数值复现（修复前）

用模拟数据（棋盘格 4000×3000 / ps=3；相纸 20000×15000 / scale=4 / ps=6）：

```
显示源 display_src   = chess.jpg        ← 错误：相纸已加载，但显示源没切
期望标记坐标 expected = (333.33, 250.00)  ← (8000/4)/6
实际绘制坐标 actual   = (666.67, 500.00)  ← (8000/4)/3  (用了棋盘格 ps)
错位 offset           = 333.33, 250.00 px
比例 ratio            = 2.000            ← 正好是 ps 之比 6/3
```

新扫描图与棋盘格的尺寸比例越不同，错位越明显——这解释了「换新图后特别明显」。

## 4. 修复（3 处，均为 3 行级）

| # | 位置 | 改动 |
|---|---|---|
| 1 | `_on_image_loaded()` | 加载完成后立即 `self._preview_src = src`，把显示源切到刚加载的图（相纸） |
| 2 | 新增 `_show_main_preview()` | 把预览切回主流程相纸图并重绘（统一入口，含异常兜底） |
| 3 | `_on_step_clicked()` | 离开标定页（idx != 0）时调用 `_show_main_preview()`，防止"标定预览后回相纸页仍用棋盘格比例" |

设计约束：`_pv()` 仍按"当前显示图"换算（这是 G07 的正确语义：标定预览不覆盖主流程图）；修复的是**显示源必须与画布同步**。

## 6. 影响范围与临时规避

- 影响：**v4.0 所有包**。触发前提是「标定后导入的相纸与棋盘格图降采样比例不同」——通常都不同，所以只要按标准流程走就会中招。
